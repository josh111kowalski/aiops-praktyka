Hooki w Claude Code: jak to działa

Hook to Twój skrypt, który Claude Code uruchamia sam w określonym momencie sesji. Model go nie wywołuje i nie może go pominąć. Poniżej przebieg jednego wywołania narzędzia i całego cyklu sesji. Wybierz scenariusz, żeby zobaczyć, co się dzieje krok po kroku.

1. Jedno wywołanie narzędzia

Claude chce uruchomić narzędzie, np. Bash. Wybierz komendę:

Komenda, którą chce wykonać Claude
kubectl get pods -n prod
Wykonane Wynik wraca do Claude.
przeszło czeka na Ciebie zablokowane pominięte

    Kolejność na schemacie odpowiada dokumentacji: hook PreToolUse sprawdza wywołanie jako pierwszy. Jego blokada wygrywa z allow, ale jego zgoda nie zdejmuje reguły deny. Przy zmianach wersji Claude Code zweryfikuj tę kolejność w aktualnych dokumentach.

    2. Co hook dostaje i co zwraca

    Claude Code przekazuje hookowi dane zdarzenia przez stdin w formacie JSON. Hook odpowiada kodem wyjścia.

    stdin (uproszczony przykład)
    {
  "hook_event_name": "PreToolUse",
  "tool_name": "Bash",
  "tool_input": {
    "command": "terraform destroy -auto-approve"
  }
}
    skrypt hooka: block-danger.sh
    #!/bin/bash
CMD=$(jq -r '.tool_input.command')
if echo "$CMD" | grep -qE 'terraform destroy'; then
  echo "Zablokowane: wymaga ręcznego wykonania." >&2
  exit 2
fi
exit 0

    3. Cykl całej sesji

    Hooki działają nie tylko wokół narzędzi. Kliknij zdarzenie, żeby zobaczyć, kiedy się odpala.

    4. Gdzie to się przydaje w DevOps

    Blokada destrukcji

    PreToolUse: terraform destroy, kubectl delete ns wymagają ręcznego wykonania.

    Lint po zmianie

    PostToolUse: po edycji .tf leci terraform fmt i tflint.

    Filtr sekretów

    UserPromptSubmit: blokuje prompt z kluczem AWS albo kluczem prywatnym.

    Kontekst startowy

    SessionStart: wypisuje aktywny klaster, branch i wersje narzędzi.

    Powiadomienie

    Notification: gdy Claude czeka na zgodę przy długim playbooku, wysyła wiadomość na Slacka.

    Audyt subagenta

    SubagentStop: zapisuje wynik i czas do audit.log.
